# 밸런스 조정 기록

v0.9.0에서 처음으로 숫자에 근거해 밸런스를 맞췄다. 사람이 손으로 몇 판 해 보는 대신, **실제 게임 엔진으로 봇이 수천 판을 플레이**하게 하고 그 결과로 수치를 정했다.

## 목표

| 난이도 | 목표 클리어율 (신중형 봇) |
|---|---|
| 쉬움 | 약 60% |
| 보통 | 약 30% |
| 어려움 | 약 12% |
| 지옥 | 약 3% |

봇은 사람보다 단순하게 플레이한다. 그래서 실제 사람의 클리어율은 이보다 조금 높을 것으로 본다.

## 방법

`src/test/java/com/renovandelve/sim/BalanceSimulation` — 기본 테스트 실행에서는 꺼져 있다(`RD_SIM=true`일 때만 돈다).

- **엔진은 진짜다.** `GameEngineService`, `GameStateService`, 저장소, Redis 세션을 그대로 쓴다. 화면이 부르는 서비스 메서드를 봇이 똑같이 부른다.
- **AI만 뺐다.** `MonsterRagService`가 실패하게 두면 엔진이 원래 가진 폴백(랜덤 몬스터, 기본 조우)으로 노드를 만든다. 회고·망령 대사·프리페치·임베딩 동기화는 목이라 LLM 비용이 없다. 왕국 정세는 균형으로 고정했다.
- **따로 떨어진 저장소.** 시뮬레이션 전용 DB(`renova_sim`)와 Redis(6380)를 쓴다. 게임 ID가 개발용 Redis 세션과 겹치지 않게 하려는 것이다.
- **봇 3종** (`BotPolicy`)
  - 신중형: 안전한 길, 천상의 선택, 계약 거절, 예상 피해가 HP의 35%를 넘으면 방어
  - 균형형: 인간의 선택, 체력이 낮으면 은밀한 길
  - 탐욕형: 위험한 길, 마계의 선택, 계약 서명, 방어는 거의 안 함
  - 공통: 원정 준비에서 예산 안의 가장 비싼 무기·갑옷·투구·스킬, 쓸 수 있는 가장 센 스킬, HP 35% 아래면 물약, 보상은 유물 > 더 센 스킬 > 물약
- 원인을 가를 때는 탐욕형의 행동을 하나씩만 켠 봇(`DANGER_ONLY`, `ABYSS_ONLY`, `CONTRACT_ONLY`, `RECKLESS_ONLY`)을 썼다.

```bash
# 시뮬레이션 전용 DB와 Redis (최초 1회)
docker exec pgvector-rd psql -U postgres -c "CREATE DATABASE renova_sim;"
docker exec pgvector-rd psql -U postgres -d renova_sim -c "CREATE EXTENSION vector; CREATE EXTENSION hstore; CREATE EXTENSION \"uuid-ossp\";"
docker run -d --name redis-sim -p 6380:6379 redis:7

# 실행 (결과는 build/balance-report.md)
RD_SIM=true RD_SIM_DB_URL='jdbc:postgresql://localhost:5433/renova_sim' RD_SIM_DB_PASSWORD=... \
  RD_SIM_REDIS_PORT=6380 RD_SIM_RUNS=150 RD_SIM_POLICIES=CAUTIOUS,BALANCED,GREEDY \
  ./gradlew test --tests '*BalanceSimulation' --rerun
```

1,800판(난이도 4 x 봇 3 x 150판)에 약 30분 걸린다.

## 무엇을 바꿨나

### 1. 몬스터 기준 능력치 (`R__seed_data.sql`)

예전 보통 표에 **난이도 배율**과 **스테이지 곡선**을 곱했다. 방어력은 그대로다.

- 난이도 배율: 쉬움 1.245 / 보통 1.31 / 어려움 1.36 / 지옥 1.415
- 스테이지 곡선: 1.12 / 1.10 / 1.10 / 1.08 / 1.00 (앞 스테이지를 조금 더 세게)

| 스테이지 | 쉬움 HP/공격 | 보통 | 어려움 | 지옥 |
|---|---|---|---|---|
| 1 | 84 / 11 | 88 / 12 | 91 / 12 | 95 / 13 |
| 3 | 178 / 23 | 187 / 24 | 194 / 25 | 202 / 26 |
| 5 | 299 / 37 | 314 / 39 | 326 / 41 | 340 / 42 |

**알아 둘 점**: 난이도 사이의 적 능력치 차이가 작아졌다. 난이도의 차이는 방어력과 **보상 배율**(쉬움 0.7배, 지옥 2배)에서 크게 온다. 지옥은 보상이 두 배라 성장이 빨라서, 적이 조금만 더 세도 어려움과 비슷해진다. 난이도를 "적이 훨씬 세다"로 느끼게 하고 싶다면 지옥의 보상 배율을 낮추고 적을 더 올리는 방향이 있다(다음 조정 후보).

기존 DB에도 들어가도록 시드에 `UPDATE`를 붙였다(파일이 바뀌면 Flyway가 다시 실행한다).

### 2. 함정이던 선택을 고쳤다

탐욕형이 모든 난이도에서 0~3%여서, 행동을 하나씩 켜 보며 원인을 찾았다(보통 난이도, 100판씩).

| 행동 하나만 켠 봇 | 조정 전 | 조정 후 |
|---|---|---|
| 기준 (신중형) | 25% | 35% |
| 위험한 길 | **0%** | 23% |
| 마계의 선택 | **2%** | 31% |
| 계약 서명 | 32% | (변경 없음) |
| 방어를 덜 함 | 50% | (변경 없음) |

- **위험한 길**: 적 +25% → **+10%**, 보상 +50%를 점수·골드뿐 아니라 **경험치에도** 적용. 예전에는 위험을 감수해도 실제로 강해지는 것이 없었다.
- **마계**: 천상은 회복, 인간은 골드가 있는데 마계에는 버틸 수단이 없었다.
  - 마계의 낙인에 **흡혈**(준 피해의 2 / 4 / 5%)을 더했다.
  - 받는 피해 대가를 +10/12/14% → +5/7/9%로 낮췄다(공격력은 +12/18/24% → +12/18/25%).
  - 마계 조우는 유물 30% → 40%, 골드 증가, 피해 감소로 바꿨다.
  - 흡혈 6%는 너무 강해서(마계만 67%) 두 번 낮췄다.
- **계약서**는 손익이 맞아서 그대로 뒀다.
- **방어를 덜 하는 쪽이 오히려 유리했다**: 신중형 봇이 너무 자주 방어한다는 뜻이다. 사람은 이보다 잘할 것이다. 방어 태세 자체의 수치는 바꾸지 않았다.

## 조정 후 (v0.9.0, 각 150판)

| 난이도 | 신중형 | 균형형 | 탐욕형 | 전투당 턴 (신중형) |
|---|---|---|---|---|
| 쉬움 | 51~68% (측정 4회 평균 약 62%) | 62% | 84% | 4.4 |
| 보통 | **33%** | 39% | 63% | 4.7 |
| 어려움 | **9~11%** | 13% | 42% | 5.1 |
| 지옥 | **4%** | 5% | 25% | 5.5 |

- 150판의 오차는 약 ±4%p다. 쉬움은 같은 근처 배율에서 측정마다 51~74%로 흔들려 평균으로 정했다.
- 전투가 2~3턴 → 4~5턴으로 길어져, 행동 예고를 보고 방어·대상을 고를 여지가 생겼다.
- 탐욕형이 신중형보다 높다. 공격적인 플레이(위험한 길, 방어 최소화)가 보상받는 정도로 봤다.

## 아직 남은 것

- **사망 지점이 마지막 보스에 몰려 있다** (보통에서 사망의 약 90%가 보스전). 스테이지 곡선으로 앞쪽을 올렸지만 스테이지 1~3의 사망은 여전히 거의 없다. 몬스터 등급 배율(보스 HP 3.2배, 공격 1.7배)은 코드 상수라 이번에는 건드리지 않았다.
- **봇이 모르는 것**: 상점에서 장비를 사지 않고, 유물 조합을 노리지 않고, 스킬 조합 시너지를 고려하지 않는다. 사람은 이것들로 더 강해진다.
- **손맛은 측정하지 못했다.** 직접 플레이하며 다듬어야 한다.
