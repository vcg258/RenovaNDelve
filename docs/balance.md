## v0.12.0: 등급·콘텐츠 확장 뒤 다시 맞춤

### 왜 다시 맞췄나

봇이 상점에서 장비를 바꿔 끼우고 등급이 높은 유물부터 고르게 하자(사람이 실제로 하는 것), v0.9.0 수치로는 **모든 난이도가 98~100% 클리어**됐습니다. 장비·스킬·유물이 늘어난 것도 한몫했습니다. 직접 플레이하며 느낀 "초반에 좋은 장비가 다 나와 버린다"와 같은 이야기입니다.

### 결과 (봇마다 100판)

| 난이도 | 목표 (신중형) | 신중형 | 균형형 | 탐욕형 | 신중형 사망 중 보스에서 |
|---|---|---|---|---|---|
| 쉬움 | 60% | 70% | 77% | 88% | 60% |
| 보통 | 30% | 35% | 34% | 62% | 66% |
| 어려움 | 12% | 13% | 23% | 40% | 49% |
| 지옥 | 3% | 2% | 6% | 16% | 45% |

100판 측정은 ±5%p 안팎으로 흔들립니다. 쉬움은 목표보다 조금 높게 남겼습니다.

### 바꾼 것

1. **몬스터 기준표를 깊이에 따라 올렸습니다.** 스테이지 1은 거의 그대로(장비가 없는 시작이라 조금만 세져도 곧바로 쓰러집니다), 깊을수록 많이 올렸습니다. 상점 장비·레벨·유물로 강해지는 속도를 따라가게 하려는 것입니다.

   | 스테이지 | HP 배율 | 공격 배율 |
   |---|---|---|
   | 1 | 1.03 | 1.02 |
   | 2 | 1.20 | 1.10 |
   | 3 | 1.40 | 1.19 |
   | 4 | 1.55 | 1.25 |
   | 5 | 1.55 | 1.25 |

2. **난이도 차이를 깊이에 따라 벌렸습니다.** 난이도 배율(쉬움 1.11 / 보통 1.125 / 어려움 1.15 / 지옥 1.17)이 스테이지 1에서는 40%만 걸리고 스테이지 5에서는 다 걸립니다. 처음에는 같은 배율을 모든 스테이지에 걸었더니 지옥은 첫 스테이지에서 절반 가까이 쓰러졌습니다.
3. **보스 배율을 낮췄습니다** (HP 3.2 → 2.8배, 공격 1.7 → 1.55배). 그 대신 일반 몬스터를 올렸습니다. v0.9.0에서 남은 문제였던 "사망이 마지막 보스에 몰린다"(쉬움·보통 사망의 80~100%)가 45~66%로 줄었습니다.

### 봇을 바꾼 것

| 무엇 | 전 | 후 |
|---|---|---|
| 상점 | 유물과 회복 물약만 산다 | 지금보다 보너스가 큰 장비 → 유물(등급 높은 것부터) → 더 센 스킬 → 물약 순. 물약 하나 값은 남긴다 |
| 전리품 유물 | 첫 번째 | 등급이 가장 높은 것 |
| 방어 | 위험하면 매 턴 막는다 | 두 턴 연속으로는 막지 않는다 |

방어를 바꾼 이유: 몬스터를 올리자 신중형 봇이 매 턴 "위험하다"고 판단해 방어만 하다가 끝내 쓰러졌습니다. 사람은 그렇게 하지 않으므로 봇을 고쳤습니다.

### 바꾼 값의 위치

- 몬스터 기준표: `src/main/resources/db/migration/R__seed_data.sql`의 `seed_monster_base_status`
- 보스·엘리트 배율: `GameEngineServiceImpl.newSessionMonster`
- 등급 확률: `game/engine/RarityTable`

## v0.9.0: 처음 맞춤

### 한눈에 보기

- **조정 전**: 쉬움·보통은 사실상 질 수 없었고(클리어율 100%), 지옥은 아무도 깰 수 없었습니다(0%). 전투는 2~3턴이면 끝났습니다.
- **조정 후**: 난이도마다 목표한 만큼 어려워졌습니다. 보통은 3판 중 1판쯤, 지옥은 25판 중 1판쯤 클리어합니다. 전투는 4~5턴으로 길어졌습니다.
- **덤으로 찾은 것**: "위험한 길"과 "마계의 선택"은 고르면 손해만 보는 함정이었습니다. 둘 다 고쳐서 이제 해볼 만한 선택지가 됐습니다.

| 난이도 | 목표 | 조정 전 | 조정 후 |
|---|---|---|---|
| 쉬움 | 10판 중 6판 | 10판 중 10판 | 10판 중 약 6판 |
| 보통 | 10판 중 3판 | 10판 중 10판 | 10판 중 약 3판 |
| 어려움 | 100판 중 12판 | 100판 중 38판 | 100판 중 약 10판 |
| 지옥 | 100판 중 3판 | 0판 | 100판 중 약 4판 |

> 위 숫자는 "신중하게 플레이하는 봇" 기준입니다. 사람은 봇보다 영리하게 플레이하니(상점 장비, 유물·스킬 조합) 실제로는 조금 더 잘 깰 것으로 봅니다.

---

### 어떻게 맞췄나

사람이 직접 몇 판 해 보는 대신, **컴퓨터가 게임을 수천 판 플레이하게 했습니다.**

- 진짜 게임 서버를 그대로 쓰고, 화면에서 버튼을 누르는 것과 똑같은 요청을 봇이 보냅니다.
- AI(서사 생성)만 빼고, AI가 실패했을 때 게임이 원래 쓰는 방식(랜덤 몬스터, 기본 장면)으로 대신했습니다. 그래서 비용이 들지 않고 빠릅니다.
- 한 번 측정에 1,800판, 약 30분이 걸립니다.

#### 봇은 세 종류입니다

| 봇 | 성격 | 이렇게 플레이합니다 |
|---|---|---|
| **신중형** | 조심스러운 초보 | 안전한 길만 가고, 조우에서는 천상을 고르고, 계약서는 거절하고, 위험하면 일찍 방어합니다 |
| **균형형** | 평범한 플레이어 | 인간의 선택을 하고, 다치면 은밀한 길로 숨어 갑니다 |
| **탐욕형** | 공격적인 숙련자 | 위험한 길, 마계의 선택, 계약서 서명을 고르고 방어는 거의 하지 않습니다 |

세 봇 모두 원정 준비에서는 예산 안의 가장 좋은 장비와 스킬을 사고, 전투에서는 쓸 수 있는 가장 센 스킬을 씁니다. 체력이 낮으면 물약을 마십니다.

**목표 클리어율은 신중형 봇 기준**으로 맞췄습니다.

---

### 플레이어가 느낄 변화

1. **적이 단단해졌습니다.** 한 방에 끝나던 전투가 4~5턴 이어집니다. 적이 "강공"을 예고할 때 방어할지 버틸지 고민할 여지가 생겼습니다.
2. **위험한 길이 할 만해졌습니다.** 적이 조금 세지는 대신 경험치·골드·점수를 50% 더 줍니다. 예전에는 적만 세지고 실제로 강해지는 것이 없었습니다.
3. **마계가 버틸 수 있게 됐습니다.** 마계 쪽으로 기울면 준 피해의 일부를 체력으로 돌려받습니다(흡혈). 예전에는 천상(회복)이나 인간(골드)과 달리 버틸 수단이 없었습니다.
4. **난이도별 체감**: 쉬움도 이제 방심하면 집니다. 지옥은 여전히 아주 어렵지만 불가능하지는 않습니다.

### 무엇을 바꿨나

#### 1. 몬스터를 더 단단하게

모든 난이도에서 몬스터의 체력·공격력을 올렸습니다. 초반 스테이지를 조금 더 많이 올려, 앞부분이 너무 쉽지 않게 했습니다.

| 예시 (보통 난이도) | 조정 전 | 조정 후 |
|---|---|---|
| 스테이지 1 몬스터 기본 체력 / 공격력 | 60 / 8 | 88 / 12 |
| 스테이지 5 몬스터 기본 체력 / 공격력 | 240 / 30 | 314 / 39 |

#### 2. 함정이던 선택 두 가지

탐욕형 봇이 모든 난이도에서 거의 깨지 못해서, 탐욕형의 행동을 하나씩만 켠 봇으로 원인을 찾았습니다(보통 난이도, 각 100판).

| 이것만 바꾼 봇 | 조정 전 | 조정 후 | 무엇을 고쳤나 |
|---|---|---|---|
| (기준) 신중형 | 25% | 35% | — |
| 위험한 길만 감 | **0%** | 23% | 적 강화 +25% → +10%, 보상 50%를 경험치에도 |
| 마계만 고름 | **2%** | 31% | 흡혈 추가, 받는 피해 대가 축소, 마계 조우 보상 상향 |
| 계약서에 서명함 | 32% | — | 손익이 맞아서 그대로 |
| 방어를 덜 함 | 50% | — | 오히려 유리 → 신중형 봇이 너무 자주 방어한다는 뜻 |

흡혈은 처음에 너무 세게 넣었다가(마계만 골라도 67% 클리어) 두 번 낮췄습니다.

#### 3. 조정 후 세 봇 비교 (각 150판)

| 난이도 | 신중형 | 균형형 | 탐욕형 |
|---|---|---|---|
| 쉬움 | 약 62% | 62% | 84% |
| 보통 | 33% | 39% | 63% |
| 어려움 | 9~11% | 13% | 42% |
| 지옥 | 4% | 5% | 25% |

탐욕형이 가장 잘 깹니다. 위험을 감수하는 공격적인 플레이가 보상받는 정도로 봤습니다.

### 스킬 조합과 가호 단계 (각 300판)

스킬 조합을 노리는 **조합형 봇**(`SYNERGY`)을 더해 두 가지를 쟀습니다. 조합형은 스킬을 고르고 바꿀 때 켜지는 조합 시너지 수를 점수에 넣습니다.

#### 스킬 조합 배율에 상한이 필요한가

빈틈 찌르기(x1.25)와 재앙의 조율(x1.15)이 함께 켜지면 곱해집니다. 조합형 봇은 이 둘을 함께 켜는 비율이 3~14%에서 66~77%로 늘었지만, 클리어율은 신중형과 표본 오차(약 ±4%p) 안에서 같았습니다. 상한은 두지 않았습니다.

| 난이도 | 신중형 클리어 | 조합형 클리어 | 두 배율 동시 (신중형 → 조합형) |
|---|---|---|---|
| 쉬움 | 66% | 67% | 3% → 74% |
| 보통 | 38% | 37% | 9% → 73% |
| 어려움 | 12% | 10% | 11% → 76% |
| 지옥 | 3% | 4% | 12% → 70% |

조합을 고려하지 않는 봇도 6종 중 5종(피의 연계, 번지는 불길, 상처에 스민 독, 휩쓸기, 재앙의 조율)을 75~100% 켭니다. 빈틈 찌르기만 노려야 켜집니다.

#### 가호 단계 기준 3 / 6 / 9 → 3 / 7 / 12, 헌신 보상

기준이 3 / 6 / 9일 때 한 세력만 고르는 탐욕형은 82~95%가 3단계에 닿았고, 평균 31~32번째 노드(한 판 약 50노드)였습니다. 그 뒤 남은 조우 2~4번은 어느 세력을 골라도 차이가 없었습니다.

기준을 3 / 7 / 12로 올리고, 3단계 기준을 넘긴 세력을 다시 고를 때마다 **헌신 보상**(천상 최대 HP +6, 마계 공격력 +2, 인간 골드 +60)을 주었습니다.

| 지표 (탐욕형) | 3 / 6 / 9 | 3 / 7 / 12 |
|---|---|---|
| 3단계 도달 | 82~95% | 55~72% |
| 도달 노드 (평균) | 31~32 | 37~40 |
| 도달 뒤 조우 (평균) | 3.3~3.8 | 2.0~2.3 (헌신 보상이 붙는다) |
| 클리어율 쉬움 / 보통 / 어려움 / 지옥 | 91 / 64 / 39 / 19% | 92 / 71 / 39 / 17% |

신중형의 클리어율도 오차 안에서 그대로였습니다(쉬움 68 → 66%, 지옥 5 → 3%). 봇은 모닥불 서원을 쓰지 않으므로, 서원까지 하는 사람은 3단계에 더 빨리 닿습니다.

#### 은밀한 길 대가 -30% → -20% (각 200판)

플레이어 피드백("기습 한 번에 비해 대가가 너무 크다")을 재려고 **매번 은밀한 길만 가는 봇**(`AMBUSH_ONLY`)을 더했습니다. 길 말고는 신중형과 같습니다. 클리어율은 쉬움 / 보통 / 어려움입니다.

| 대가 | 매번 은밀한 길 | 신중형 | 균형형 |
|---|---|---|---|
| -30% (이전) | 57 / 26 / 10% | 68 / 36 / 14% | 73 / 45 / 21% |
| -20% (채택) | 72 / 44 / 24% | 62 / 40 / 14% | 77 / 45 / 15% |
| -10% | 83 / 58 / 29% | 64 / 34 / 12% | 69 / 45 / 18% |

-30%에서는 경험치까지 깎여 레벨이 덜 올라, 매번 고르면 손해였습니다. -10%에서는 매번 고르는 것이 모든 난이도에서 가장 잘 깨서 길을 고를 이유가 사라집니다. -20%에서는 균형형과 비슷한 수준(어려움만 조금 높음)이라 이 값을 골랐습니다.

### 부록 (개발자용)

#### 측정 오차

150판으로 잰 클리어율은 대략 ±4%p 흔들립니다. 쉬움은 비슷한 설정에서도 측정마다 51~74%로 흔들려서, 네 번 잰 평균으로 정했습니다.

#### 바꾼 값

- **몬스터 기준 능력치** (`src/main/resources/db/migration/R__seed_data.sql`): 예전 보통 표 x 난이도 배율(쉬움 1.245 / 보통 1.31 / 어려움 1.36 / 지옥 1.415) x 스테이지 곡선(1.12 / 1.10 / 1.10 / 1.08 / 1.00). 방어력은 그대로. 시드에 `UPDATE`가 있어 기존 DB에도 반영됩니다.

  | 스테이지 | 쉬움 HP/공격 | 보통 | 어려움 | 지옥 |
  |---|---|---|---|---|
  | 1 | 84 / 11 | 88 / 12 | 91 / 12 | 95 / 13 |
  | 2 | 123 / 16 | 130 / 17 | 135 / 18 | 140 / 19 |
  | 3 | 178 / 23 | 187 / 24 | 194 / 25 | 202 / 26 |
  | 4 | 242 / 31 | 255 / 33 | 264 / 34 | 275 / 35 |
  | 5 | 299 / 37 | 314 / 39 | 326 / 41 | 340 / 42 |

- **위험한 길** (`PathChoice`): 적 배율 1.25 → 1.10, 보상 배율(1.5)을 경험치에도 적용 (은밀한 길의 0.7도 경험치에 적용)
- **마계의 낙인** (`Alignment`): 흡혈 0 / 2 / 4 / 5%(단계별), 받는 피해 1.10/1.12/1.14 → 1.05/1.07/1.09, 공격력 1.12/1.18/1.24 → 1.12/1.18/1.25
- **마계 조우** (`GameEngineServiceImpl.buildEncounterChoices`): 유물 30 → 40%, 골드 50+20x스테이지 → 60+25x스테이지, 피해 14+4x스테이지 → 8+2x스테이지

#### 시뮬레이터 실행

코드는 `src/test/java/com/renovandelve/sim/`에 있고, 평소 테스트에서는 꺼져 있습니다(`RD_SIM=true`일 때만 돕니다). 개발용 데이터와 섞이지 않게 전용 DB와 Redis를 씁니다.

```bash
# 최초 1회: 시뮬레이션 전용 DB와 Redis
docker exec pgvector-rd psql -U postgres -c "CREATE DATABASE renova_sim;"
docker exec pgvector-rd psql -U postgres -d renova_sim -c "CREATE EXTENSION vector; CREATE EXTENSION hstore; CREATE EXTENSION \"uuid-ossp\";"
docker run -d --name redis-sim -p 6380:6379 redis:7

# 실행 (결과는 build/balance-report.md)
RD_SIM=true RD_SIM_DB_URL='jdbc:postgresql://localhost:5433/renova_sim' RD_SIM_DB_PASSWORD=... \
  RD_SIM_REDIS_PORT=6380 RD_SIM_RUNS=150 RD_SIM_POLICIES=CAUTIOUS,BALANCED,GREEDY,SYNERGY \
  ./gradlew test --tests '*BalanceSimulation' --rerun
```

- 원인을 가를 때 쓰는 봇: `DANGER_ONLY`, `AMBUSH_ONLY`, `ABYSS_ONLY`, `CONTRACT_ONLY`, `RECKLESS_ONLY` (`RD_SIM_POLICIES`에 넣는다)
- 난이도만 골라 돌리려면 `RD_SIM_DIFFICULTIES=NORMAL`
